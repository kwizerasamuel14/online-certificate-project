# Up Skills Hub — Online Certificate Module

Frontend for the **Online Certificates** feature of the Up Skills Hub website, built
from the supervisor's feature documents. Built as a standalone, responsive frontend
module — ready to be integrated into the main Up Skills Hub site and connected to
the backend APIs when available.

## Features

- **Request Certificate form** — trainee/intern information (name, ID validation in
  `USH-TRA/INT-YEAR-####` format, program dropdown with all ~50 programs grouped by
  category, dates), completion info, optional document uploads (PDF/DOCX/ZIP, max 10 MB),
  self-declaration, success screen with **Pending Review** status.
- **My Certificates (student)** — notifications, list of earned certificates
  (view / download / share), list of own requests with **View / Edit / Cancel**
  (edit and cancel allowed only while *Pending Review*).
- **Admin Certificate Management** — search, filter by status, trainer
  **Recommend**, admin **Approve & Generate** (issues a unique certificate number
  like `USH-2026-FD-000002`, notifies the student), regenerate PDF, email,
  revoke with reason.
- **Certificate Details** — certificate preview, QR code pointing to the public
  verification URL, download, share/copy link.
- **Public verification** (`verify.html`) — enter a certificate number or scan the
  QR code with the camera; shows *Valid* / *Certificate Not Found* / *Certificate Revoked*.
- Responsive (desktop / tablet / mobile), loading states, error handling, toasts.
- Matches the Up Skills Hub brand (Lato, `#1f0bb6`, `#3F9DA8`).

## Workflow

Trainee submits → Pending Review → Trainer reviews → Trainer recommends →
Admin approves → Certificate generated by the system → Trainee receives a
notification and can download the certificate.

## Running

No build step and no server required — open `index.html` in a browser,
or serve the folder with any static file server.

Use the role switcher in the header (Trainee / Trainer / Admin) to walk through
the full approval workflow.

## API integration

All data access goes through a single API layer in `js/api.js`. Every function maps
to a documented REST endpoint (see `ENDPOINTS` in that file). Currently it serves
mock data (`data/mock-data.js`) with simulated latency; when the backend is ready,
set `API_CONFIG.baseUrl` and replace the mock responses with `fetch` calls —
no page code needs to change.

## Tech

Plain HTML / CSS / JavaScript (no framework), QRCode.js, html5-qrcode for scanning.
